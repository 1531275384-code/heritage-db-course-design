## 三、一个必须解释的差集：DROP 11 次 vs CREATE 10 次

机械计数会看到 `DROP TRIGGER IF EXISTS` 有 **11** 条，`CREATE TRIGGER` 只有 **10** 条。
差的那一个是 `trg_audit_record_immutable`。

这不是遗漏，是**有意的历史清理**，源文件第 230–239 行有注释说明：

- 早期在 `audit_record` 上挂了 `trg_audit_record_immutable`（`BEFORE UPDATE OR DELETE` → `fn_forbid_modify`）；
- 它对**任何** UPDATE 都抛异常，而专家终审本身就是 `UPDATE audit_record SET state='approved'`，
  挂上就把整条终审链路堵死；
- 后来拆成两个分工更细的触发器：`trg_audit_record_no_delete`（一律禁删）+
  `trg_audit_record_guard`（禁改已终审，放行状态迁移）；
- 保留 `DROP ... IF EXISTS` 是为了兼容**旧库升级**：老库里那条触发器还在，脚本要先摘掉它。

而且这个结论有回归防护，不靠注释自证 —— `tests/test_invariants.py:154-159`：

```python
# 回归防护：曾有 trg_audit_record_immutable（BEFORE UPDATE OR DELETE → fn_forbid_modify），
# 它会拦掉终审所需的 UPDATE
assert re.search(r"CREATE\s+TRIGGER\s+trg_audit_record_immutable\b[^;]*?BEFORE\s+UPDATE", sql02, re.I) is None
```
