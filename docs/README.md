回答「系统是什么、怎么用、数据可信吗」。三份都是**结论性文档**，
不含代码细节，适合直接转给别人看。

| 文件 | 内容 | 读者 |

## 三、命名约定

本目录及 `output/` 下统一遵守三条：

1. **编号前缀表示阅读顺序**，不表示重要程度。`01` 先看，`04` 基本不用看。
2. **目录名用中文**，因为要交给不看代码的人；**代码目录用英文**（`app/ sql/ tests/ scripts/`），因为要被工具链解析。
3. **不带日期的名字表示「当前有效」**。任何被后续工作推翻的结论，移到 `04-归档/` 并在文件开头注明作废时间，不删除——保留判断轨迹比保持目录干净更值钱。

## 四、与 output/ 的分工

容易混，一句话分清：

| | `docs/` | `output/` |
|---|---|---|
| 本质 | 说明与证据（Markdown / 日志） | 可交付成品（docx / html / png / zip） |
| 能不能改 | 手写，随时改 | 脚本生成，**改了会被覆盖** |
| 给谁 | 要理解项目的人 | 要提交或展示的人 |

`output/` 的组织方式见 `output/产物清单.md`。
两个目录里的 docx 是**同源不同物**：`docs/03-选题材料/选题报告.md` 是源，`output/01-交付物/*.docx` 是排版后的成品。
