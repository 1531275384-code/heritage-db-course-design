> 这份文档回答三个问题：**怎么启动**、**打开后能看到什么**、**数据是从哪来的**。
>
> 面向"要演示给评审看"的场景，不需要读源码。

## 1. 三条命令

```bash
# ① 直接看界面（无需数据库，数据在进程内存里）
python bootstrap.py --demo

# ② 严格用真库（需先按 README 建库 + 跑 sql/01~03）
python bootstrap.py --strict

# ③ 把演示数据灌进真库（在 ① 的基础上让真库也有同样的内容）
python -m scripts.init_seed
```

启动后浏览器打开 `http://127.0.0.1:8000/`，登录页有"演示账号（点击直填）"，
  
点一下自动填好账号口令，再点「登录」即可。

| `heritor02` | 龙妹银 | 传承人   | 作品上传 / 母题库 / 我的作品         |
| `expert01`  | 周文渊 | 评审专家  | 作品上传 / 母题库 / 专家工作台 / 监管台账 |

## 2. 五个页面分别能看什么

### 2.1 作品上传

拖一张图片进来 → 填名称 → 点「上传并触发 AI 分析」。右侧面板实时显示：

- AI 判定档位（公有母题 / 改编衍生 / 原创）与置信度
- Top-5 相似公有母题的相似度条
- 特征模型名、向量维度、命中规则
- 相似私有资产（查重）

**关键点**：这一页的结论只是"建议"。资产此刻是 `pending` 状态，权属级别还没定。

### 2.2 母题库 ★新增

这是分级判定的**比对基准**——每件作品都要跟它做向量近邻检索。

页面结构：

1. **四步说明条** — 母题入库 → 作品提特征 → 近邻检索 → 阈值分级，
     
   讲清母题库在整个流程里的位置
2. **母题卡片墙** — 每条母题一张卡，含参考图、编号、族属、地域、年代、
     
   分类、关键词、描述，以及技术信息（特征模型、向量维度、已被多少作品引用）
3. **筛选** — 全部 / 已被作品引用 / 暂未被引用
4. **母题与作品的关联表** — 展示 `asset.motif_id`（母题血缘）这张关系，
     
   带相似度条与 AI/专家一致性标记，可直接跳到溯源

> **血缘为什么要单独一张表**：`asset.motif_id` 只在判定为"公有母题"或"改编衍生"
>   
> 时才回写，原创作品留空。这避免了给原创作品无端挂上一个公有母题的来源——
>   
> 那会削弱原创作者的权益主张。

### 2.3 我的作品

本人全部作品列表：AI 建议、专家结论、审核状态、版本号、创建时间。
  
已确权的作品可以「授权」，草稿/驳回的可以「AI 分析」。

### 2.4 专家工作台

待终审队列（数据源：视图 `v_asset_pending_audit`）。点「终审」打开模态：

- 左侧是 AI 的相似度报告与创作说明
- 右侧选最终档位、填意见
- 提交后同一个事务内：改审核流水 → 改资产权属 → 触发器写审计日志

**专家可以推翻 AI**。种子数据里的「缠枝莲纹双面绣屏风」就是这种情况：
  
AI 判 public（0.9247），专家看过工艺细节后改判 derived，系统记为 `is_override`。

### 2.5 监管台账

全平台资产宽表（视图 `v_asset_ledger`）+ 三个统计卡：

- 在册资产数（按级别分布）
- **授权费用合计 ¥131,600**（5 笔生效授权）
- 审计日志条目数 + AI/专家一致率

点任意作品的「溯源」可看完整链路：资产登记 → AI 预审 → 专家终审 → 授权流转，
  
每个节点附数据库触发器写入的新旧快照。

## 4. 这些 AI 数字不是编的

种子里写的 `ai_suggest_level` / `ai_confidence` / `similarity` **全部是真实算法算出来的**，
  
不是手填的假数据。验证方式：

```bash
python -m scripts.check_seed
```

输出会逐件比对"算法结果 vs 种子记录"，不一致就报错。这个脚本是提交前的护栏：

```
 id  作品                         算法判定      种子判定          相似度     置信度  结论
  1  苗绣蝴蝶纹袖片（杨氏改良版）             derived   derived    0.8349  0.4741  ✓
  2  原创鱼纹蜡染方巾                   original  original   0.4486  0.5691  ✓
  4  蝴蝶纹样直接复制件                  public    public     0.9970  0.6356  ✓
  ...
全部一致：种子里的 AI 结论确实是真实算法算出来的。
```

**为什么要在意这一点**：如果种子里的 AI 结论是编的，演示时会出现诡异现象——
  
台账显示 derived，但点「AI 分析」重跑一遍变成 original。评审方一眼看出数据是假的，
  
整套演示的可信度归零。

改了图片之后重跑：

```bash
python -m scripts.check_seed --write   # 用当前算法结果覆盖 JSON 里的 AI 字段
```

## 5. 数据是怎么加载的

```
data/seed_demo.json
        │
        ├──→ app/demo.py :: DemoStore.reset()          进程内存（演示模式）
        │       └── warm_all() 在启动时算母题/作品向量
        │
        └──→ scripts/init_seed.py                      真实 PostgreSQL
                └── 灌入 8 张表，ON CONFLICT 幂等
```

两条路径**共用同一份 JSON**，所以切库时界面内容一模一样——
  
只有顶部的红色「演示模式」横幅会消失，数据库约束开始真正生效。
  
这正是演示要传达的差别。

几个环境变量：

| 变量              | 默认     | 作用                                |
| --------------- | ------ | --------------------------------- |
| `ICH_DEMO_MODE` | `auto` | `1` 强制演示 / `0` 强制真库 / `auto` 自动降级 |
| `ICH_DEMO_SEED` | `on`   | 设为 `off` 则只加载兜底账号与母题（用于演示"空库首屏"）  |

### 仍未验证的（诚实声明）

> **更新（2026-11-08）**：下列内容已失效——便携版 PostgreSQL 16.2 已在本机跑起来，
> 见 `docs/verify/pg_run.log`（35 项通过 / 0 失败 / 1 缺口）。列级 GRANT、CHECK/UNIQUE/外键、
> 8 个触发器、`FOR UPDATE` 行锁、事务回滚、专家终审主链路**均已实测**。
> 只剩一项：HNSW 索引未实测（便携包不含 pgvector，走 `NUMERIC[]` 精确扫描）。
> 原先的第二项「未终审不得授权」已补成数据库约束 `trg_license_require_approved`。
> 以下原文保留，作为当时的记录。

- **SQL 从未在真实 PostgreSQL 上执行过**。本机安全策略禁止 `initdb`，
    
  也没有 C 编译器装不了 pgvector。所有 SQL 都只做了静态结构检查。
- 因此下列数据库特性**只是代码里写了，没有被运行证明**：
    
  列级 `GRANT` 拦截、`CHECK` / `UNIQUE` / 外键约束、真实 `AFTER` 触发器、
    
  HNSW 索引、MVCC 并发与 `FOR UPDATE` 行锁、事务回滚。
- 演示模式用 Python 锁与手工留痕**模拟**了这些行为，逻辑等价但不是数据库保证。

演示模式顶部的红色横幅就是在说这件事——不要把它当成"数据库已经验证过了"。

## 8. 演示脚本建议（5 分钟版）

1. **登录**（30 秒）：点 `heritor01` 快捷登录，指出顶部红色横幅——
     
   先坦白"这是内存数据，不是真库"，后面的展示才可信
2. **母题库**（1 分钟）：四步说明条讲清母题库是比对基准；
     
   翻三张卡片，指出"向量维度 512 / 特征模型 builtin"是真实算出来的
3. **我的作品**（30 秒）：3 件作品覆盖已确权 / 待审核 / 草稿三种状态
4. **切到专家**（1.5 分钟）：登录 `expert01`，工作台有 2 件待终审；
     
   点开「回纹织锦改良坐垫」，看 AI 报告 → 选档位 → 提交 →
     
   提示"触发器已写入审计日志 #N"
5. **监管台账**（1 分钟）：统计卡显示 ¥131,600 授权费；
     
   点「溯源」看完整链路，指出每个节点都带新旧快照
6. **回到首页**（30 秒）：说明真库模式下红色横幅会消失，
     
   而列级 GRANT / 触发器 / HNSW 才开始真正生效
7. **收尾一句**（10 秒）：传承人不仅看不到监管台账，直接连库改权属状态也会被触发器拒绝。
     
   `audit_status` 这一列必须给传承人写权限（草稿、提交待审都要用），所以列级授权堵不住
   "自己把状态推到已确权"；堵它的是 `trg_asset_status_guard`。真库上以 `ich_heritor`
   身份执行 `UPDATE asset SET audit_status='approved'`，返回的是数据库的 42501，
   不是应用层的 403 —— 这条负向用例在 `tests/check_pg.py` 第 13 节。
